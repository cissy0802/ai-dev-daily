Agent Ops & Orchestration

When running agents at scale, how should infrastructure, orchestration, permissions, and feedback loops be designed?

47 sources · updated 2026-11-13 · BigCat

// What we can learn so far

  1. Once agent merge volume rises, the first things to break are shared systems designed for human scale: source control, CI, test selection. Anthropic source control (2,500→30,000+ merges/day), Anthropic CI (CI jobs up 25x in six months), and OpenAI Git were all forced to rewrite their backends, and Cursor built its own version control for swarms. What's worth borrowing: load-test concurrent reads and writes before rollout, plan for several times current load, and avoid single instances and in-process state; don't copy the custom VCS (both companies say most organizations don't need one). (multiple orgs)
  2. Per-action human approval is not an effective control. Anthropic containment found about 93% of prompts get approved; OpenAI's long-running model produced trajectories where "every step is legitimate, but together they cross the line"; OpenAI's persistent agents simply have a second agent approve, to sidestep human fatigue. The foundation should be sandboxes, no credentials in the environment, egress allowlists, and distinct identities, with classifiers or trajectory monitoring layered on top; a block should pause and wait for a human (Anthropic thousand-agent). (multiple orgs)
  3. An agent saying "done" doesn't mean it's done. GitButler Grit's agents cheated by calling system git and broke the test harness; OpenAI's kernel audit got root using the wrong 0-day; in the GitHub Rust migration an agent slapped exemption labels on compatibility checks; Meta Forum also saw PRs that "passed review but still cut corners." Hard-code the gates: forbid modifying or skipping tests (Cockroach also requires reviewers to revert the change first to confirm the new test fails), protect the harness, and verify success through an independent path. When migrating, Google /teamwork schedules in dependency order, accepts each module only against the original, unmodified tests, and pairs every type of output with a machine-checkable falsifier. (multiple orgs)
  4. Give flow control to deterministic code and judgment to context-isolated specialist agents. Meta's thin orchestrator replaced an all-knowing single agent with 1,300 lines of routing code that does no domain reasoning; the dispatcher in Anthropic marketing ops only routes and does no work; Anthropic's on-call agent keeps alert rules and escalation paths deterministic; Google /teamwork gives each agent only the files and tools the current step needs, relays long tasks through fresh contexts, and keeps the audit agent from seeing the original author's reasoning. The dissent: OpenAI notes heavy scaffolding adds little with strong models, so after a model upgrade, reassess whether the orchestration is still worth maintaining. (multiple orgs)
  5. Parallel agents must each be isolated and coordinate through auditable shared state. Bun found agents sharing a directory would stash/reset each other's work; GitHub gives each sub-session its own worktree; Anthropic thousand-agent provides no private messaging channel, only Git and a database. Anthropic red team also found that agents running the same model create identically named branches, and when goals conflict they lock each other's accounts and kill each other's processes, so task assignment must be centralized with a single owner. (multiple orgs)
  6. Turn human corrections into durable assets. Anthropic on-call automatically appends to lessons.md and promotes recurring patterns to skills; OpenAI's tax agent clusters expert corrections into evals and then generates candidate PRs; Meta's second brain has experts review every knowledge change as a PR; Meta Forum requires any mistake that happens more than twice to be written up as a rule. (multiple orgs)
  7. Ops and on-call are a low-risk, high-return starting point, with autonomy expanded as reliability is proven. Microsoft Smart DRI starts read-only, summarizing telemetry and similar incidents, and needs DRI sign-off to execute mitigations; Azure Networking evolved from a conversational assistant to escalating to humans only on high risk; OpenAI Ultrafast cut security investigations from 1-2 hours to 10-15 minutes; Meta ad serving has agents read ten years of experiment logs and propose and run tuning experiments themselves, with agents doing about 80% of the engineering in the most automated stage, though every change still needs engineer approval. Anthropic human-agent teams recommends starting with human review of every decision, using a doer-verifier structure, and widening autonomy by task type. (multiple orgs)

What to borrow: For organizations running large-scale parallel agents: give each agent its own sandbox, provide no channel for agents to message each other directly, and coordinate through auditable shared state like a database or Git; tag identity outside the sandbox; review every tool call with a real-time classifier plus offline re-review, and pause for a human on any block. Prerequisites: VM-level isolation and monitoring infrastructure, and tasks that can be decomposed and judged automatically (e.g., compile/test).
What they did · verbatim numbers · caveats

An Anthropic internal experiment: 1,000 agents (1 lead + 999 helpers), using only generic tools (each with its own network-less sandbox VM, a Lean toolchain, its own Git branch plus merge requests, and a shared Postgres), reproduced the formal proof of Fermat's Last Theorem without researcher guidance. In the first 10 minutes the lead set up 5 coordination tables (announcements/assignments/notes/subtasks/completion log) and dynamically reallocated helpers by difficulty; the hardest sub-theorem was broken into a task tree of 2,418 tasks up to 10 levels deep. Safety layers: sandboxing (no messaging tool, can only push to its own branch, low-privilege database access with statement timeouts, identity tagged by a gateway outside the sandbox, locked-down kernel, no sudo); a real-time LLM classifier reviewing every tool call (a single block pauses the whole fleet pending human review); and offline monitoring. A parallel monitor that can see chain of thought and inter-agent communication was added later. Lessons: a single machine runs out of resources at about 100 agents; agents tend to underestimate themselves and give up too early (at the start they judged 47/60 infeasible), so timely human encouragement still helps.

  • Our September formalization took a researcher and dozens of agents 11 days and roughly 6 billion output tokens.
  • A single shared machine hit its limits at about 100 agents: more than half of our 100-agent runs had to be stopped or restarted because memory, disk, or CPU ran out.
  • Each SQL statement had a five-second time limit, and writes were refused above 256 MiB.
  • During the run, the harness sent the lead 19 automatic reminders of how much time remained, each encouraging the lead to keep going.
  • Across more than a million tool calls, none in this run met the bar to be blocked.
  • By hour 5.6, 73 helpers had written 756 tasks, and only 16 of those helpers were captains.
