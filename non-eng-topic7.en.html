// What we can learn so far

  1. Accuracy is mainly an engineering problem of context and verification, and a stronger model won't fix it. Without skills, the Anthropic data team's eval accuracy topped out at 21%; with skills it exceeded 95%, but drifted to about 65% after a month without maintenance, so skills and data models now go in the same PR. GitHub Qubot has each data owner contribute context, with every change passing evals. When reports were inaccurate, the Microsoft PM team fixed the source data first. (multiple orgs)
  2. Keep human approval on anything sent externally and on changes to systems of record. Anthropic BDR runs CRM updates as "proposal + evidence + human approval" and logs rejection reasons; Anthropic finance and the OpenAI CFO both have AI draft and humans sign; Anthropic legal uses a two-layer process where AI does first review and lawyers re-check flagged items. Anthropic marketing later dropped pre-send approval; non-lab organizations should first assess the cost of an erroneous external send. (multiple orgs)
  3. Lock in every human correction so it stays in effect. Anthropic marketing wrote feedback into 9 explicit rules in the first week (including "never fabricate URLs"); Anthropic legal has Claude propose instruction updates weekly based on lawyer feedback, effective only once approved; Meta runs expert corrections through evals, regression tests, and PR review before merging them into knowledge files. (multiple orgs)
  4. Start with narrow, repetitive tasks. Anthropic growth marketing's five points (multiple inputs, produces a single file, recurs, you know what good looks like, a tedious compile-and-reconcile middle) can be used directly to pick first tasks; GitHub legal started with triaging one type of notice and wrote the methodology as plain-text instructions in a repo; OpenAI finance used hackathons where the front line brought problems and technical staff paired with them. (multiple orgs)
  5. Personal tools should be validated before entering a team's shared library, and need an owner. Anthropic BDR skills are validated individually before being promoted into the team plugin; Anthropic sales tools are packaged as a plugin and set as the default onboarding configuration, and the person who built them became a full-time GTM architect ("about 80% of sales use it" doesn't define usage); after duplicate agents appeared, Microsoft PM switched to promoting reusable skills. (multiple orgs)
  6. Build operational guardrails to production-system standards. Anthropic Japan BDR centrally hosts credentials, grants least privilege per agent, and versions instruction changes; the Anthropic data agent reads only the governed layer, masks PII at the column level, and tags every query with the requester; Meta privacy classification handles about 85% of requests with deterministic rules, with the LLM only as fallback; a scheduled job at GitHub marketing failed silently for five days because it had no failure alerting. (multiple orgs)
  7. Nearly all outcome figures in this category are single-person self-estimates from vendors' promotional series, e.g. Anthropic marketing ops's "two days down to two hours" and Japan BDR's "about 60 hours saved"; the control group for the Anthropic buying agent's "2x conversion" was self-selected by customers. Borrow the practices, but re-measure the results against your own baseline. (vendor self-reported)
